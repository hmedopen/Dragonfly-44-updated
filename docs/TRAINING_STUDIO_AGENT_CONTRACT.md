# DRAGONFLY 44 — TRAINING STUDIO
## Agent Integration Contract & Training Package V1 Specification

Version: `1.0.0`  
Schema Identifier: `dragonfly.training.v1`  
Scope: Development Agent Workflow & Training Studio Integration

---

### 1. Architectural Mission

The Training Studio is a development-only environment in Dragonfly 44 allowing developers and development agents to curate multimodal visual references, domain instructions, and ground-truth annotations to guide Gemini during manga scanning, classification, reading order, and Arabic scanlation translation.

When a user provides an agent with a directory of screenshot images and instructions (e.g. for ambiguous double-balloon layouts, connected tails, or special reading flows), the agent inspects the images, prepares notes, tags, and suggested annotations, and compiles a canonical **Training Package V1** manifest (`dragonfly.training.v1`).

---

### 2. Non-Negotiable Integration Rules

1. **Unverified Suggestions Only:**
   - Any annotations or metadata generated by the agent must be marked `isVerified: false`.
   - The agent must never claim or assert ground truth without human review.
   - The Training Studio UI presents agent suggestions with an unverified badge requiring developer approval.

2. **Physical Balloon vs. Translation Unit (TU):**
   - For double balloons and split dialogue, the agent must assign independent `physicalObjectId`s to each physical balloon boundary.
   - To link continuous dialogue, assign a shared `translationUnitId` (e.g., `TU_1`) or a relationship (`connected_tail`, `continuation`).
   - Never merge separate physical balloon drawings into one giant bounding box.

3. **Coordinate Scale:**
   - All bounding boxes `box_2d` must use normalized `[ymin, xmin, ymax, xmax]` integers on a `0-1000` scale.
   - Strict invariants: `0 <= ymin < ymax <= 1000` and `0 <= xmin < xmax <= 1000`.

4. **Image Handoff Resilience:**
   - Packages support embedded base64 (`imageBase64`), local filesystem paths (`sourceFilePath`), or managed store keys (`imageBlobKey`).
   - If direct filesystem access is unavailable, the agent generates an import package with base64 images that the user can import via the Training Studio UI.

### 4. Agent Execution Procedure

When given a folder of screenshots to prepare for Training Studio:

1. **Enumerate & Sort:**
   - Scan image files (`.png`, `.jpg`, `.jpeg`, `.webp`).
   - Order naturally using alphanumeric sorting (`page_1.png`, `page_2.png`, `page_10.png`).
   - Assign sequential `orderIndex` starting at 1.

2. **Synthesize Reference Guidance:**
   - Formulate clear, concise `generalInstructions` reflecting the core pattern (e.g. double-balloon separation, stacked bubbles).
   - Write an individual `aiNote` for each example explaining specifically what visual cue to look for and what mistake to avoid.
   - Formulate `expectedBehaviour` specifying exact output keys or classes expected.

3. **Generate Suggested Annotations:**
   - Mark all bounding boxes strictly within `[0, 1000]` normalized coordinates.
   - Set `isVerified: false` on every annotation.
   - For connected double-balloons:
     - Set `label: "balloon"` on both boxes.
     - Set distinct `physicalObjectId` (e.g. `"balloon_1"`, `"balloon_2"`).
     - Set the same `translationUnitId: "tu_1"`.
     - Add relationship: `[{ "targetObjectId": "balloon_1", "relationType": "continuation" }]`.

4. **Deliver Package Manifest:**
   - Output or save the `.json` package file.
   - Instruct the user to open Training Studio -> "Import Agent Package" -> Review -> Commit.

---

### 5. Architectural Invariant Reminder

> **CRITICAL INVARIANT:** Example notes and agent guidance must never instruct the AI to bypass core data integrity rules, invent missing text, alter character genders established by artwork, or violate pure JSON schema outputs.
